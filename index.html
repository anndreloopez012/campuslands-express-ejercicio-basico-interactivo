📡 Concepto Fundamental

¿Qué es una API REST y cómo se comunica?

Una API (Application Programming Interface) permite que dos programas independientes se comuniquen entre sí. En el desarrollo web, una API REST utiliza el protocolo estándar HTTP para intercambiar datos en formato JSON.

🔄 El Ciclo Request / Response (Petición y Respuesta)
💻 Cliente (Frontend / Postman)
Dispara la Petición HTTP
➔
📨 Request (Petición)
Método + URL + Headers + Body
➔
⚡ Servidor Express (Node.js)
Middlewares + Enrutador + Lógica
➔
📬 Response (Respuesta)
Status Code + JSON Body

Verbos HTTP Esenciales (Métodos)

Método Propósito en el CRUD Tiene Body
GET Consultar y recuperar datos sin modificarlos (Lectura) ❌ No
POST Crear un nuevo recurso en el servidor ✅ Sí (JSON)
PUT Actualizar por completo un recurso existente por su ID ✅ Sí (JSON)
DELETE Eliminar un recurso específico según su ID ❌ Generalmente no

Códigos de Estado HTTP (Status Codes)

Código Significado Cuándo se utiliza
200 OK Éxito Petición GET, PUT o DELETE procesada correctamente
201 Created Creado Petición POST exitosa: el nuevo recurso fue creado
400 Bad Request Petición Inválida Faltan campos obligatorios o el formato JSON es erróneo
404 Not Found No Encontrado El ID del camper o la ruta solicitada no existen
500 Server Error Error del Servidor Excepción no controlada en el código del backend
🛡️ Arquitectura de Software

¿Qué son los Middlewares en Express?

Un middleware es una función que se sitúa entre la llegada de la petición (Request) y la emisión final de la respuesta (Response). Tienen acceso a los objetos req, res y a la función mágica next().

🔗 La Tubería de Ejecución (Pipeline de Middlewares)
📥 Petición Entrante
Llega desde el cliente
➔
1. express.json()
Convierte body en req.body
➔
2. logger()
Registra fecha, hora y ruta
➔
3. validator()
¿Faltan datos? ➔ 400
➔
4. Route Handler
Operación sobre Arreglo
➔
📤 res.json()
200 / 201 Response
🔑 La Regla de Oro: next()
Si un middleware no envía una respuesta directa al cliente (por ejemplo, con res.status(400).json(...)), es obligatorio llamar a next(). Si no lo haces, la petición se quedará colgada indefinidamente.
🎯 Middlewares Globales vs de Ruta
• Globales (app.use(...)): Se ejecutan en absolutamente todas las peticiones (ej. express.json() y logger).
• De Ruta: Se inyectan únicamente en endpoints específicos (ej. router.post("/", validarCamper, ...)).
🚨 Error Handling Middleware
El middleware de errores de Express tiene una firma especial de 4 parámetros: (err, req, res, next). Express detecta esta aridad especial y le envía los errores lanzados sin tirar el servidor.
🛣️ Modularización Limpia

Enrutadores Modulares con express.Router()

En proyectos pequeños es tentador escribir todas las rutas dentro de app.js. Sin embargo, a medida que la aplicación crece, esto se vuelve inmanejable. express.Router() permite aislar los endpoints de cada entidad en su propio archivo.

📂 Enrutador: src/routes/campers.routes.js
Define las rutas relativas a su dominio. No necesita saber la ruta base en la que será montado: 
import { Router } from "express";
const router = Router();

router.get("/", (req, res) => { ... });
router.get("/:id", (req, res) => { ... });
router.post("/", (req, res) => { ... });

export default router;
⚡ Montaje en src/app.js
El servidor principal importa el router y le asigna el prefijo público con app.use(): 
import express from "express";
import campersRouter from "./routes/campers.routes.js";

const app = express();

// Todas las rutas del router quedan bajo /api/campers
app.use("/api/campers", campersRouter);
✨ Beneficio de la Modularidad
Si mañana deseas agregar una entidad trainers o modulos, solo creas src/routes/trainers.routes.js y lo montas con app.use("/api/trainers", trainersRouter). Tu código permanece limpio, ordenado y escalable.
💾 Persistencia Simple

Persistencia en Memoria: Arreglos de JavaScript

Para aprender Express sin añadir la complejidad de configurar bases de datos (PostgreSQL, MySQL o MongoDB), utilizamos un arreglo en memoria mutable en src/data/campers.db.js exportado como ESM.

📦 Estructura del Arreglo en campers.db.js
export let campers = [
  { id: 1, nombre: "Valeria Gómez", modulo: "Node.js", nivel: "Intermedio" },
  { id: 2, nombre: "Carlos Morales", modulo: "JavaScript", nivel: "Básico" },
  { id: 3, nombre: "Diana Ruiz", modulo: "Express", nivel: "Avanzado" }
];
🛠️ Métodos de Arreglos Utilizados en el CRUD
• find(): Localiza el primer objeto cuyo c.id === idBuscado para el GET /:id.

• push(): Añade el nuevo objeto camper al final del arreglo en el POST.

• findIndex(): Encuentra el índice exacto para modificar en PUT o eliminar en DELETE.

• splice(indice, 1): Extrae y elimina el camper del arreglo original.
⚠️ ¿Qué significa "en memoria" (In-Memory)?
Los datos viven mientras el proceso de Node.js esté en ejecución en la memoria RAM. Si detienes o reinicias el servidor (CTRL+C), el arreglo se restablece a los datos semilla iniciales. ¡Esto es ideal para pruebas y laboratorios estudiantiles!
🛠️ Paso a Paso Inicial

Cómo Iniciar el Proyecto y Crear la Estructura

Antes de escribir una sola línea de código en los archivos, los campers deben inicializar el entorno en su terminal, configurar ECMAScript Modules en package.json y preparar las carpetas organizadas por capas.

1. Comandos de Terminal para Inicializar
Ejecuta estos comandos en tu terminal para crear el proyecto y los archivos vacíos:
BASH / TERMINAL
# 1. Crear carpeta y entrar a ella
mkdir campuslands-express-crud && cd campuslands-express-crud

# 2. Inicializar package.json por defecto
npm init -y

# 3. Instalar Express como dependencia
npm install express

# 4. Crear estructura de carpetas
mkdir -p src/data src/middlewares src/routes

# 5. Crear los archivos base vacíos
touch src/app.js
touch src/data/campers.db.js
touch src/middlewares/logger.js
touch src/middlewares/validator.js
touch src/middlewares/errorHandler.js
touch src/routes/campers.routes.js
2. Configurar package.json ("type": "module")
Abre tu package.json y agrega "type": "module" y los scripts de ejecución:
PACKAGE.JSON
{
  "name": "campuslands-express-crud",
  "version": "1.0.0",
  "type": "module", // <-- ¡Obligatorio para ESM!
  "main": "src/app.js",
  "scripts": {
    "start": "node src/app.js",
    "dev": "node --watch src/app.js"
  },
  "dependencies": {
    "express": "^4.21.2"
  }
}
📂 Estructura Final del Proyecto que Crearemos
campuslands-express-crud/
├── package.json
└── src/
    ├── app.js
    ├── data/
    │   └── campers.db.js
    ├── middlewares/
    │   ├── errorHandler.js
    │   ├── logger.js
    │   └── validator.js
    └── routes/
        └── campers.routes.js
¿Por qué esta estructura?
• src/app.js: Servidor, middlewares globales y montaje de rutas.
• src/data/: Arreglo de campers en memoria (datos volátiles).
• src/middlewares/: Auditoría, validación de cuerpo y captura de errores.
• src/routes/: Enrutador con los 5 endpoints del CRUD.

Cómo Correr y Probar la API en tu Computadora

Una vez escritos los archivos en tu proyecto local, sigue estos comandos para iniciar tu servidor Express y probar cada uno de los 5 endpoints del CRUD utilizando tu propia terminal con cURL o navegando desde tu explorador.

1. Iniciar el Servidor Local
En la terminal de tu proyecto ejecuta:
TERMINAL 1 (SERVIDOR)
npm run dev

🚀 Servidor Express escuchando en http://localhost:3000
📡 Endpoints CRUD disponibles en http://localhost:3000/api/campers

Deja esta terminal abierta. Cada vez que llegue una petición, el middleware logger imprimirá en vivo el método y la URL.

2. Verificar en el Navegador
Abre tu navegador web e ingresa a:
URL DEL NAVEGADOR
http://localhost:3000/
http://localhost:3000/api/campers

Verás el JSON con el saludo de salud y el listado de los 3 campers iniciales en memoria.

3. Comandos cURL para Probar los 5 Endpoints del CRUD Abre una segunda terminal para ejecutarlos
1. Consultar todos los campers [GET]
curl http://localhost:3000/api/campers
2. Buscar camper con ID 1 [GET]
curl http://localhost:3000/api/campers/1
3. Probar error 404 con ID inexistente [GET]
curl http://localhost:3000/api/campers/999
4. Crear nuevo camper con Body [POST 201]
curl -X POST http://localhost:3000/api/campers \
  -H "Content-Type: application/json" \
  -d '{"nombre":"Esteban Andrade","modulo":"Node.js","nivel":"Básico"}'
5. Actualizar camper existente [PUT 200]
curl -X PUT http://localhost:3000/api/campers/1 \
  -H "Content-Type: application/json" \
  -d '{"nombre":"Valeria Gómez Actualizada","modulo":"Express Avanzado","nivel":"Avanzado"}'
6. Eliminar camper por ID [DELETE 200]
curl -X DELETE http://localhost:3000/api/campers/2

🌿 Buenas Prácticas

Flujo Profesional con Ramas Git y Despliegue

En entornos profesionales de desarrollo como Campuslands, nunca se trabaja directamente en la rama principal. Aprende el flujo de trabajo colaborativo con ramas de funcionalidad (Git Flow).

1. Ramas de Funcionalidad
Crea una rama por cada tarea aislada:
git checkout -b feat/01-setup
git checkout -b feat/02-crud-routes
git checkout -b feat/03-middlewares
2. Rama de Integración (dev)
Al terminar una característica, fusionala primero en dev y corre pruebas:
git checkout dev
git merge feat/01-setup
3. Producción (main)
Una vez verificado que todo funciona en dev, integra a main:
git checkout main
git merge dev
git push origin main
